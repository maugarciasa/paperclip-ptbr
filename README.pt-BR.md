# O Paperclip é o aplicativo que as pessoas usam para gerenciar agentes de IA no trabalho.

Orquestração de código aberto para equipes de agentes de IA.

**Se o OpenClaw é um _colaborador_, o Paperclip é a _empresa_.**

O Paperclip é um servidor Node.js e interface de usuário React que orquestra uma equipe de agentes de IA para tocar um negócio. Traga seus próprios agentes, atribua metas e acompanhe o trabalho e os custos a partir de um único painel. Escolha modelos e harnesses por agente enquanto mantém as tarefas, habilidades, permissões e histórico da sua equipe centralizados em um só lugar.

Ele se parece com um gerenciador de tarefas. Sob o capô: organogramas, orçamentos, governança, alinhamento de metas e coordenação de agentes.

**Gerencie metas de negócios, não pull requests.**

|        | Etapa            | Exemplo                                                            |
| ------ | ---------------- | ------------------------------------------------------------------ |
| **01** | Definir a meta   | _"Construir o app nº 1 de notas com IA até atingir \$1M de MRR."_   |
| **02** | Contratar a equipe | CEO, CTO, engenheiros, designers, marketing — qualquer bot, qualquer provedor. |
| **03** | Aprovar e rodar  | Revise a estratégia. Defina orçamentos. Dê a partida. Monitore tudo pelo painel. |

## O Paperclip é ideal para você se

- ✅ Você deseja construir **organizações autônomas de IA**
- ✅ Você **coordena muitos agentes diferentes** (OpenClaw, Codex, Claude, Cursor) em direção a uma meta comum
- ✅ Você tem **20 terminais do Claude Code abertos simultaneamente** e perde o controle do que cada um está fazendo
- ✅ Você quer agentes operando de forma **autônoma 24/7**, mas ainda deseja auditar o trabalho e intervir quando necessário
- ✅ Você quer **monitorar custos** e aplicar limites de orçamento
- ✅ Você quer um processo de gerenciamento de agentes que **pareça o uso de um gerenciador de tarefas**
- ✅ Você quer gerenciar suas empresas autônomas **diretamente do seu smartphone**

## Os quatro pilares

Quatro coisas precisam funcionar para que uma organização de agentes de IA realmente produza resultados: as tarefas, a organização, o treinamento e a infraestrutura. O Paperclip foi construído exatamente em torno desses quatro pilares.

| --- | --- | --- |
| **Gerenciador de Tarefas Agêntico** — Declare a intenção. Agentes trabalham. Você valida o resultado. | Todos, no dia a dia | Tarefas, aprovações e portões de revisão · colegas de equipe de IA proativos · rotinas e fluxos de trabalho auditáveis · verificação por meio de diffs, capturas de tela e testes |
| **Organograma para Agentes** — Papéis, permissões e fronteiras para humanos e agentes. | Gestores | Organograma misto de humanos + agentes · responsabilidades, delegação, especialização · governança: quem pode fazer o quê · segredos delimitados e fronteiras da empresa · permissões de conexão e identidades de usuários responsáveis |

| **Sistema Operacional Agêntico** — A infraestrutura que faz o trabalho acontecer. | TI e plataforma | Runtime multiplataforma: qualquer modelo, qualquer agente · sandboxing, integrações e servidores MCP · SSO, GRC, RBAC e controles de custo · privacidade de dados, coleta interna de traces, valor composto de dados · conexões pessoais e compartilhadas · histórico de execuções e rastreamento opcional |

## Problemas que o Paperclip resolve

| Sem o Paperclip | Com o Paperclip |
| --- | --- |
| ❌ Você tem 20 abas do Claude Code abertas e não consegue saber o que cada uma faz. Ao reiniciar, perde tudo. | ✅ As tarefas são estruturadas em tickets, as conversas são organizadas em tópicos e as sessões persistem após reinicializações. |
| ❌ Você reúne contexto manualmente de vários lugares para lembrar o seu bot do que ele realmente está fazendo. | ✅ O contexto flui da tarefa através dos objetivos do projeto e da empresa — seu agente sempre sabe o que fazer e por quê. |
| ❌ Pastas de configurações de agentes desorganizadas e você reinventando gerenciamento de tarefas, comunicação e coordenação entre agentes. | ✅ O Paperclip oferece organogramas, criação de tickets, delegação e governança prontos para uso — para você gerenciar uma empresa, não um emaranhado de scripts. |
| ❌ Loops descontrolados gastam centenas de dólares em tokens e esgotam sua cota antes mesmo de você perceber o que aconteceu. | ✅ Rastreamento de gastos, alertas de orçamento e pausas automáticas ajudam a controlar o custo do trabalho em andamento. |
| ❌ Você tem tarefas recorrentes (suporte ao cliente, redes sociais, relatórios) e precisa se lembrar de iniciá-las manualmente. | ✅ As rotinas criam tarefas atribuídas em um cronograma, com entregas e histórico de execução auditáveis. |
| ❌ Você tem uma ideia, precisa procurar o repositório, abrir o Claude Code, manter a aba ativa e monitorar cada passo. | ✅ Crie uma tarefa no Paperclip. Seu agente de programação trabalha nela até concluir. A liderança revisa o trabalho produzido. |

## Por que o Paperclip é especial

O Paperclip lida com os detalhes complexos de orquestração da maneira correta.

| | |
| --- | --- |
| **Checkout atômico de tarefas.** | Um único responsável e bloqueios de execução impedem que execuções concorrentes assumam a mesma tarefa. |
| **Contexto de trabalho persistente.** | Tarefas, comentários e documentos permanecem no Paperclip. Adaptadores compatíveis retomam sessões salvas entre execuções. |
| **Injeção de habilidades em tempo de execução.** | Agentes aprendem fluxos de trabalho do Paperclip e contexto de projetos em tempo de execução, sem necessidade de retreinamento. |
| **Governança com rollback.** | Portões de aprovação são aplicados obrigatoriamente, alterações de configuração são versionadas e alterações indesejadas podem ser revertidas com segurança. |
| **Conexões com responsabilização.** | Acesso humano, elegibilidade de agentes e permissões de ação no gateway são controles separados. Aprove uma chamada uma única vez ou salve uma regra revogável. |
| **Execução ciente das metas.** | Tarefas e projetos vinculados carregam o histórico e a linhagem dos objetivos para que os agentes entendam o "porquê", não apenas um título. |
| **Modelos de empresa portáteis.** | Exporte e importe organizações, agentes e habilidades com limpeza de segredos e tratamento de colisões. |
| **Fronteiras organizacionais.** | Verificações de acesso delimitadas por empresa mantêm o trabalho, os agentes e as atividades de cada organização separados em uma mesma implantação. |

### Os Sistemas

<table>
<tr>
<td width="50%">

**Identidade e Acesso** — Dois modos de implantação (local confiável ou autenticado), papéis e permissões humanas, chaves de API para agentes, JWTs de execução de curta duração, associações a empresas e fluxos de convite. A atribuição ao usuário responsável acompanha o trabalho por meio de delegações e conexões gerenciadas.

</td>
<td width="50%">

**Organograma e Agentes** — Agentes têm papéis, cargos, linhas de reporte, permissões e orçamentos. Exemplos de adaptadores cobrem o diagrama: Claude Code, Codex, agentes CLI como Cursor/Gemini/bash, bots HTTP/webhook como OpenClaw e plugins de adaptadores externos. Se pode receber um heartbeat, está contratado.

</td>
</tr>
<tr>
<td>

**Sistema de Trabalho e Tarefas** — Tarefas possuem vínculos com empresa, projeto, meta e pai, checkout atômico com travas de execução, dependências de bloqueio de primeira classe, comentários, documentos, anexos, produtos de trabalho, rótulos e estado de caixa de entrada. Pesquise por todo o trabalho, revise versões de documentos e deixe feedback ancorado.

</td>
<td>

**Execução de Heartbeat** — Fila de despertar com suporte a banco de dados com coalescência, checagens de orçamento, resolução de workspace, injeção de segredos, carregamento de habilidades e invocação de adaptadores. Execuções geram logs, registros de consumo e estado de sessão específico do adaptador. Recuperação delimitada trata falhas com suporte e destaca casos que exigem ação humana.

</td>
</tr>
<tr>
<td>

**Workspaces e Runtime** — Repositórios de projetos e workspaces, workspaces de execução isolados opcionais (git worktrees, branches de operadores) e serviços de runtime (servidores de desenvolvimento, URLs de pré-visualização). Provedores de sandbox estendem a execução além do host local; a disponibilidade depende do ambiente e adaptador configurados.

</td>
<td>

**Governança e Aprovações** — Fluxos de aprovação de diretoria, políticas de execução com estágios de revisão/aprovação, rastreamento de decisões, paradas obrigatórias por estouro de orçamento e comandos de pausar/retomar/encerrar agentes. Revisões configuradas governam a conclusão; aprovações de ações de conexão controlam chamadas pelo gateway de ferramentas.

</td>
</tr>
<tr>
<td>

**Orçamento e Controle de Custos** — Rastreamento de tokens e custos por empresa, agente, projeto, meta, tarefa, provedor e modelo. Políticas de orçamento com escopo, limites de aviso e paradas rígidas. A aplicação utiliza o gasto registrado; relatórios de consumo e tarefas em andamento podem atrasar uma parada.

</td>
<td>

**Rotinas e Agendamentos** — Tarefas recorrentes com gatilhos de cron, webhook e API. Políticas de concorrência e compensação (catch-up). Cada execução de rotina cria uma tarefa rastreada e acorda o agente atribuído — sem necessidade de disparos manuais.

</td>
</tr>
<tr>
<td>

**[Plugins](https://docs.paperclip.ing/administration/plugins/)** — Sistema de plugins para toda a instância com workers fora do processo, serviços de host controlados por capacidades, agendamento de jobs, exposição de ferramentas e contribuições para a interface do usuário. Estenda o Paperclip sem precisar fazer fork.

</td>
<td>

**Segredos e Armazenamento** — Segredos da empresa e valores individuais por pessoa, armazenamento criptografado de credenciais, armazenamento local ou compatível com S3, anexos e produtos de trabalho. Referências a segredos fornecem credenciais a execuções autorizadas sem expor os valores na configuração comum do agente.

</td>
</tr>
<tr>
<td>

**Atividades e Eventos** — Ações mutativas, alterações de estado do heartbeat, eventos de custo, aprovações, comentários e produtos de trabalho são gravados como atividades duráveis para que os operadores possam auditar o que aconteceu e por quê.

</td>
<td>

**[Portabilidade de Empresas](https://docs.paperclip.ing/guides/power/export-import/)** — Pré-visualize, exporte e importe pacotes organizacionais contendo agentes, habilidades e projetos, rotinas, tarefas e anexos opcionais. Valores de segredos referenciados são omitidos; revise os pacotes antes de compartilhar, pois valores simples de ambiente e caminhos locais podem permanecer. Pacotes compartilham a configuração operacional; a recuperação completa da instância utiliza backups.

</td>
</tr>
</table>

## O que o Paperclip não é

## Início Rápido (Quickstart)

Código aberto. Auto-hospedado (self-hosted). Nenhuma conta no Paperclip é necessária. Siga o [guia de início rápido passo a passo](https://docs.paperclip.ing/guides/getting-started/five-minute-path/) para configurar seu primeiro agente.

### Peça para o seu agente instalar o Paperclip

Compartilhe o [guia de instalação](https://docs.paperclip.ing/reference/cli/installation/) com seu agente.

### Ou instale você mesmo

Com o **Node.js 24.11 ou mais recente** instalado:

```bash
npx paperclipai@latest onboard --yes
```

A CLI executa a partir do cache do npm; a configuração da sua instância e os dados persistem localmente.

Consulte o [guia de instalação](https://docs.paperclip.ing/reference/cli/installation/) para instalações gerenciadas, versões fixadas, versões canary e via git-ref, atualizações, rollback, gerenciamento de serviços e desinstalação.

Para uma instância de teste manual isolada já inicializada com um agente CEO, use `test-drive`. Ela roda em primeiro plano, nunca instala serviços no sistema nem cria uma primeira tarefa, e só abre o navegador após o sucesso da configuração:

```bash
ANTHROPIC_API_KEY=... npx paperclipai test-drive
OPENAI_API_KEY=... npx paperclipai test-drive --harness codex
OPENROUTER_API_KEY=... npx paperclipai test-drive \
  --harness opencode \
  --model openrouter/anthropic/claude-sonnet-4.5
```

Cada execução sem `--data-dir` recebe um diretório temporário exclusivo e retido; seu caminho absoluto é impresso na inicialização. Passe `--data-dir` para reutilizar um existente, ou `--no-browser` para deixar a instância inicializada sem abrir o navegador. Quando executado a partir de um Git worktree vinculado, o `test-drive` também habilita a execução de tarefas nesse worktree. Veja o [guia do test-drive](https://docs.paperclip.ing/reference/cli/test-drive/) para o comportamento de credenciais e reutilização.

> **Solução de problemas: registro privado npm no `.npmrc`**
>
> Se o comando falhar com erro `E404` para `paperclipai` (ou similar) e você utiliza um registro privado do npm (como o GitHub Packages) por meio de um `~/.npmrc` global, o `npx` pode estar buscando o pacote `paperclipai` no registro privado em vez do registro público oficial.
>
> Diagnóstico:
>
> ```bash
> npm config get registry
> ```
>
> Solução de contorno (multiplataforma; força o registro público do npm para este comando):
>
> ```bash
> npx --registry https://registry.npmjs.org paperclipai@latest onboard --yes
> ```

O caminho padrão do início rápido agora adota o modo de loopback local confiável para uma primeira execução ágil. Para iniciar no modo autenticado/privado, escolha explicitamente um preset de bind de rede:

```bash
npx paperclipai@latest onboard --yes --bind lan
# ou:
npx paperclipai@latest onboard --yes --bind tailnet
```

Se você já tiver o Paperclip configurado, reexecutar o `onboard` preserva as configurações existentes. Use `npx paperclipai configure` para editar ajustes.

Ou configure manualmente:

```bash
git clone https://github.com/paperclipai/paperclip.git
cd paperclip
pnpm install
pnpm dev
```

Isso inicia a interface e a API em `http://localhost:3100`. Um banco de dados PostgreSQL embutido é criado automaticamente — sem necessidade de configuração prévia de banco de dados.

> **Requisitos:** Node.js 24.11+, pnpm 9.15+

O login por assinatura local do Claude e do Codex também necessita do Python 3 e da CLI correspondente do provedor instalada no host do Paperclip. A imagem Docker oficial já inclui ambos.

O desenvolvimento a partir do código-fonte também compila o Paperclip Runner nativo quando habilitado (o padrão para self-hosted). Instale uma toolchain Rust ou configure `PAPERCLIP_RUNNER_BINARY` para apontar para um executável pré-compilado compatível.

## Perguntas Frequentes (FAQ)

**P: Este projeto é mantido ativamente ou é apenas código descartável?**

**R:** O Paperclip é mantido ativamente pela [equipe do Paperclip](https://paperclip.ing). Já realizamos o merge de [mais de 2.700 pull requests](https://github.com/paperclipai/paperclip/pulls?q=is%3Apr+is%3Amerged).

<br/>

**P: Como é uma configuração típica?**

**R:** Localmente, um único processo Node.js gerencia uma instância integrada do Postgres e o armazenamento local de arquivos. Para produção, aponte-o para seu próprio PostgreSQL e implante como preferir. Configure projetos, agentes e metas — os agentes cuidam do restante.

Para acesso remoto, utilize o modo autenticado com bind em rede privada como o Tailscale, ou implante o servidor persistente via Docker. Consulte [modos de implantação](https://docs.paperclip.ing/reference/deploy/deployment-modes/) e o [guia do Docker](https://docs.paperclip.ing/reference/deploy/docker/).

<br/>

**P: Posso gerenciar múltiplas empresas?**

**R:** Sim. Uma única implantação pode hospedar múltiplas organizações com isolamento total de dados e verificações de acesso delimitadas por empresa.
